# Agent Chat 使用说明

Vault Agent 是 Obsidian 桌面插件。它可以通过聊天读取、搜索和修改笔记，展示计划、工具操作与文件改动。

当前版本使用插件自带的执行引擎。新聊天不再使用 OpenCode、Claude Code 或 Codex，也不需要安装这些命令行程序。旧聊天保留原来的名称并以只读方式打开。

## 连接模型

1. 在插件设置的“模型（BYOK）”中添加模型服务，填写自己的 API Key；本地 LM Studio 等免密服务可以明确选择不需要密钥。
2. 选择并启用模型。一个模型的保存记录会同时用于普通聊天、多模型对比和子任务。
3. 模型能力、推理等级和上下文容量统一在“模型（BYOK）”中设置。不要填写超过本地服务实际加载容量的数值。
4. 打开聊天，在聊天中选择模型并发送消息。基础设置只保留通知和通用选项，不再重复显示智能对话的模型配置。

模型设置中的测试会先检查连接；支持工具的模型还要完成一次不读取笔记的工具调用，并读回实际结果。只通过普通回答不代表工具能力已经通过。明确不支持工具的模型仅测试连接。

API Key 和 MCP 令牌通过 Obsidian 的密码存储保存；普通设置中只保留引用。

## 笔记操作与批准

- **计划模式**：可读取范围内的笔记，也可记录计划、待办和问题；不能修改笔记。
- **默认模式**：修改前显示目标和具体差异，批准后才执行。
- **自动模式**：仅在已经允许的范围内自动修改普通笔记。删除、移动、本机命令和不明确的外部操作仍需批准。

批准计划只表示同意计划，不会跳过后续文件操作的批准。等待批准期间可以停止；停止后到达的批准不会继续执行写入。

同一笔记被其他操作改动时，原来的改动预览可能失效。插件会重新检查，不能把旧预览直接用于新内容。

操作结果会区分未执行、已执行、部分执行和需要核对。遇到“结果尚不能确认”时，先使用恢复提示中的核对操作；核对只检查已经发生的事实，不会再次执行原操作。长笔记会分页读取，后续修改使用整份笔记的版本；笔记已变化时须重新读取。

## 待办、计划和提问

代理可以记录待办、提交计划或提出选项问题。请在对应卡片中作出选择。聊天重新打开后会恢复已经保存的状态，不会凭空把未完成事项标为成功。

等待回答时也可以暂停或关闭 Obsidian，问题会保留。已经保存的答案不会被晚到的旧窗口覆盖；重新打开后填写答案只保存选择，明确继续后才推进工作。

`/compact` 会明确调用聊天压缩。只有摘要真正生效才显示完成，原始聊天不会删除。`/stop` 用于停止，`/model` 和 `/skill` 分别用于切换模型和加载允许的技能；未知命令会给出错误，不会当成本机命令执行。

## 多模型和子任务

多模型对比使用设置中已经启用的模型；每个候选分别回答，再汇总结果。候选是只读的，不能借用主聊天的写入权限。重新打开已经完成的结果不会再次请求模型。

停用供应商后，它的模型也会从多模型选项中移除。即使汇总失败，各模型已经完成的回答仍会保留。多模型结果会随聊天保存，直接保存在库外；重新打开可查看原结果，继续恢复后也可以接着追问。

子任务与主任务共用限制，不能自行扩大权限。输入资料与允许输出的位置分别指定，获准的新文件不必预先存在。研究、审阅和多模型候选保持只读。写作子任务默认可用，其实际写入仍逐次请求批准。

主聊天回答结束后，仍在运行的后台任务会在输入框上方显示数量。可以继续发送新消息，也可以点击“停止全部后台任务”；停止过程中不能重复点击，正在编辑的草稿会保留。

每次任务额度默认允许最多 32 次实际模型请求，主任务、子任务、候选回答和压缩共同使用；用完会暂停，明确继续后追加额度，累计使用量和费用保留。每库最多同时运行两个主任务，每个主任务最多三个并发子任务、两层子任务深度。

子任务等待自己委派的助手时，会暂时让出执行位置，让下一级助手能够完成；收到结果后再继续。停止会同时停止这些下级助手。

其他聊天占满执行位置时，新发出的请求会先保存原文、选区和附件引用。等待期间关闭聊天或退出，会保留这条尚未发送的请求；重新打开不会自动发送，需要明确点击“继续”。选择停止会放弃这条待发请求。

工作进行时发出的任何消息（文字、图片、笔记、网页标签、命令和 @提及都支持）都会先排队，并以卡片形式显示在输入框上方。每条排队消息可以编辑回输入框、删除，或点击插入按钮立即加入当前正在进行的这轮工作；插入保留原始目标和累计用量，不会另外增加执行额度。不做任何操作时，本轮结束后排队消息会按顺序自动发送。斜杠命令、指定模型的自定义命令、@提及以及当前模型读不了的图片不能中途插入，只能等本轮结束后作为独立回合发送。如果插入时工作已经结束，消息会留在队列中并在本轮结束后自动发送。停止会把尚未发送的排队消息退回输入框，不会因它们再次启动工作。

运行时可在聊天的更多菜单选择“暂停并保存进度”。暂停会先处理已开始的写入，再保存进度；停止则结束整棵任务树，已发生的修改不会自动撤销。

关闭 Obsidian 会暂停后台工作。异常退出后，先查看恢复提示，再明确选择继续或终止；仅仅打开旧聊天不会自动执行未完成操作。

## MCP 和外部文件

在插件设置中与“技能”同级的独立“MCP 服务器”标签页添加 HTTP MCP 服务或显式配置本地服务。HTTP 登录可以打开系统浏览器；尚未获得有效授权的连接不能调用工具。工具搜索和工具调用都要遵守当前设置，撤销服务后旧批准失效。

工具权限采用单层模型：没有预置的执行模式或文件夹授权开关，本机命令、本地 MCP 服务和资料库外文件的唯一闸门是逐次批准卡片。资料库内部修改仍使用笔记工具并保留可撤销的变更日志。本机程序以当前系统账户运行，这不是操作系统沙盒。

加载技能只会读取其说明。说明中的代码示例不会因此自动运行；真正执行程序仍需符合当前权限并获得批准。

## 聊天记录、分叉与导出

聊天记录和图片仅保存在笔记库之外，不再自动创建聊天笔记。标题、置顶和访问时间也保存在同一处。复制的聊天链接和书签使用固定会话编号，重命名或重启后仍能打开。

聊天没有存储容量上限。长聊天先显示最近 50 条，可用“加载更早的消息”继续查看；完整记录仍保留。

“分叉为新聊天”会复制已停止的聊天记录、附件和回退资料。两份聊天各自保存，删除其中一份不影响另一份；它们操作的笔记仍属于同一个笔记库。请先结束前后台任务并处理审批，再进行分叉。

删除聊天需要确认，会永久清除原记录、附件和回退备份，无法恢复。已打开的相关标签也会关闭。另一窗口正在使用时，需要先关闭那边的会话再重试。

可主动导出 JSON 或 Markdown，并自由选择保存位置。导出副本不参与最近列表、聊天恢复或书签，删除会话不会删除副本，也不能将副本导回。

本次升级不兼容已有聊天，包括之前内置引擎的记录。原件保留但不再读取；旧聊天链接不再可用。已有模型配置和系统钥匙串密钥继续保留。

打开历史只恢复显示，不会自动执行未完成的工作。同时有两项工作占用运行位置时，其他历史聊天先显示最近保存的记录；空出位置后仍需明确继续。
