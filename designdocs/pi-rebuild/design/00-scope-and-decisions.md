# 00 · 范围、不可变决策与完成定义

## 产品范围

本重构替换的是外部 Agent 的执行/模型/工具协议，不重做聊天产品。原来的聊天、消息显示、会话索引、项目、技能、模型选择、权限弹窗、Diff、计划、任务清单、压缩、子代理、fan-out 和反馈能力均要保留并接上新运行时。[V02,V03,V08,V09]

用户路径固定为：安装插件 → 在插件设置中添加供应商与模型、凭据进入 Keychain → 选择模型 → 开始聊天 → 按需批准操作。模型推理服务仍可在云端或用户已有本地服务；“在插件进程调用”不等于模型权重在 Obsidian 内运行。

## ADR-01：唯一运行时

采用 `Harness`（pi-durable）作为执行、任务拥有关系、工具调用和恢复的唯一权威。`pi-ai` 负责模型协议，`pi-mcp` 负责 MCP 协议，`chord` 是 Durable 的状态/取消基础。原生工具来自 `pi-durable/tools`。[P01,P03,P07]

不得同时维护另一份 Core loop、Coding Agent SessionManager 或自写工具轮询循环。产品层可以管理 UI 状态和任务限制，但不能再次调用模型形成第二条循环。模型选择、多子代理共享供应商层，不等于引入第二执行引擎。

## ADR-02：权威与投影

Durable 保存完整执行记录和产品状态文档。AgentMessageStore 是显示缓存；Markdown 是用户可读导出；AgentSessionIndex 是检索索引。后两者故障不能改变执行结果；执行存储故障必须停止执行。[V05,V06,P01]

旧 Markdown、索引与原始后端记录不能被直接改写为 Pi 会话。新会话有新 ID，导入保留来源映射。导入历史不声称能恢复旧模型的隐藏状态。

## ADR-03：路由不是建议

模型只能请求能力，不能决定自己的信任等级。工具分为 Vault、外部文件、Obsidian 动作、MCP 和宿主命令。宿主根据工具注册元数据、规范化目标、用户授权与会话模式决定能否执行。拒绝时返回结构化错误，工具本身不能跳过审查。

## ADR-04：公开 API 与固定版本

所有 Pi 直接依赖使用 `1.3.0`，不用 `^`、`~`、Git main 或运行时远程下载。SDK 类型仅进入 `sdk/pi/`；业务界面消费本项目类型。新生产层只建一个 `sdk/pi/` 子树，遵守现有边界，不新增泛化框架。

## ADR-05：同进程与外部执行的界限

Agent 循环、模型请求、调度、工具审批均在插件运行环境中。用户主动批准的 shell/stdio MCP 会创建 OS 子进程，这是工具行为，不是另起 Agent daemon。禁止后台下载解释器、npm 包或 Agent 二进制。不要使用 `process.execPath` 假定它是 Node CLI；在 Electron 中它可能是 Obsidian 可执行程序。

## ADR-06：保留能力但不伪造数据

ReasoningBlock 只显示供应商实际公开返回的 thinking/reasoning。无此内容的模型仍能回答，思考文本显示不可用，不让模型伪写。订阅额度在 BYOK 无来源时不可显示假百分比；改用明确标记的本地预算窗口，且统计来源真实。[V12,P09]

## ADR-07：安全默认值

默认 plan/只读子代理不写任何用户资源；default 模式 Vault 写操作确认；auto 仅免除已授权范围的低风险修改确认，不免除删除、移动、Shell、未知 MCP 与权限扩大。未知工具、未知效果、未知路径均拒绝或明确请求授权，绝不默认安全。

## ADR-08：阶段可运行

迁移中旧后端可作为临时开发回退，但一阶段的演示必须真实运行该阶段新能力。发布前删除旧执行依赖，保留纯历史读取代码。不能以切回旧 Claude 后端作为 Pi 新功能验收成功。

## 完成定义

全部任务 done，全部阶段 gate 有证据，功能矩阵每一行由新引擎生产事件并经过重载回放测试；干净机器只有支持版本 Obsidian 与插件即可完成核心路径；旧数据不丢；取消和崩溃不会未经批准重复副作用；无 Keychain 密钥泄漏；未执行测试必须显示未执行，不能写“推测通过”。

明确不在本次范围：任意远程代码扩展市场、自动安装 MCP 服务器、任意脚本的跨平台 OS 沙盒、服务器化多用户部署、离线本地大模型安装。它们不应用来延后当前渲染功能的实现。
