## 操作步骤

1. 读取实际git状态与根AGENTS。
2. 填写当前commit、未提交改动归属和PoC证据位置。
3. 将P00保留accepted_user_report，不重复实验。
4. 记录真实支持的Obsidian版本或未知字段，不猜测。
5. 建立真实issue关联方式，不在代码里造链接。

先核对已有证据与实际文件，不填猜测结果。

## 必须成立的断言

- `SC-P01-T01-01`：已有未提交修改内容保持不变。
- `SC-P01-T01-02`：P00仍为完成。
- `SC-P01-T01-03`：原PoC无路径时明确标用户确认而非失败。

本任务是后续产品能力的真实基础设施，不允许用空成功实现骗过依赖。

## 验证命令

在仓库根执行（测试文件路径是本任务需要建立的目标，不是声称现已存在）：

```sh
node designdocs/pi-rebuild/scripts/check-plan.mjs
```

新增视觉状态还需按仓库流程加入相邻story并检查gallery。阶段结束按阶段文件运行完整lint/build/review；不能用文档检查器替代生产测试。代码任务必须有非零匹配测试数，测试未运行不得done。

## 退出标准与证据

以上断言全部通过；没有新增未经审查的副作用路径；原功能不回退。将实际命令、退出码、文件变更、scenario ID 和已知限制写入 `execution/evidence/P01-T01.json`，status=passed后才更新STATE为done。没有提交写gitCommit=null；没有真实平台的证据写not_run而非passed。

## 跨会话交接

未完成就保持本ID的in_progress/verify_failed。HANDOFF写明停在第几步、哪个函数、当前diff、已跑哪些断言、下一条应运行的命令。不得到下一会话重新领取后面的任务，把本任务遗忘。任务结束运行check-plan并更新currentTaskId/nextTaskId。
