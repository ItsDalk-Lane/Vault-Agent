执行完整工程审查与发布资料。只实现下面列出的行为，不借机重做UI、替换另一执行框架或加入未批准的后台服务。

本任务为文档/人工验收任务，所列源码只作为检查基线，不擅自修改生产逻辑。

## 操作步骤

1. 运行format/lint/unit/build/review:obsidian与gallery。
2. 核对源许可与第三方声明流程。
3. 复核全部阶段gate和feature证据。
4. 写数据位置与可信执行风险说明。
5. 不自动发布或上传用户数据。

先核对已有证据与实际文件，不填猜测结果。

## 必须成立的断言

- `SC-P14-T07-01`：必需命令实际exit0且非零测试数。
- `SC-P14-T07-02`：所有gate证据完整。
- `SC-P14-T07-03`：无未标注能力限制。
- `SC-P14-T07-04`：未执行外部发布保持未执行。

本任务是后续产品能力的真实基础设施，不允许用空成功实现骗过依赖。

## 验证命令

在仓库根执行（测试文件路径是本任务需要建立的目标，不是声称现已存在）：

```sh
node designdocs/pi-rebuild/scripts/check-plan.mjs
```

新增视觉状态还需按仓库流程加入相邻story并检查gallery。阶段结束按阶段文件运行完整lint/build/review；不能用文档检查器替代生产测试。代码任务必须有非零匹配测试数，测试未运行不得done。

## 退出标准与证据

以上断言全部通过；没有新增未经审查的副作用路径；原功能不回退。将实际命令、退出码、文件变更、scenario ID 和已知限制写入 `execution/evidence/P14-T07.json`，status=passed后才更新STATE为done。没有提交写gitCommit=null；没有真实平台的证据写not_run而非passed。

## 跨会话交接

未完成就保持本ID的in_progress/verify_failed。HANDOFF写明停在第几步、哪个函数、当前diff、已跑哪些断言、下一条应运行的命令。不得到下一会话重新领取后面的任务，把本任务遗忘。任务结束运行check-plan并更新currentTaskId/nextTaskId。
