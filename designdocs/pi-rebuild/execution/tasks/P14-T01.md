## 操作步骤

1. 从真实producer逐行驱动现有组件。
2. 每行绑定scenario和证据。
3. 错误/取消/无数据状态也验。
4. 恢复回放结果与运行中一致。
5. 未实现行不通过隐藏组件删掉。

先写能复现下列行为的失败测试，再实现。依赖对象使用注入，不能mock掉本任务核心逻辑。异步等待明确Promise/事件，禁止sleep碰运气。

## 必须成立的断言

- `SC-P14-T01-01`：全部feature有非story-only证据。
- `SC-P14-T01-02`：不存在frontend-only功能。
- `SC-P14-T01-03`：所有终态区分真实失败。
- `SC-P14-T01-04`：功能ID不遗漏。

本任务是后续产品能力的真实基础设施，不允许用空成功实现骗过依赖。

## 验证命令

在仓库根执行（测试文件路径是本任务需要建立的目标，不是声称现已存在）：

```sh
npm test -- --runInBand --runTestsByPath src/agentMode/sdk/pi/__tests__/featureCoverage.test.ts
npm run build:esbuild
```

新增视觉状态还需按仓库流程加入相邻story并检查gallery。阶段结束按阶段文件运行完整lint/build/review；不能用文档检查器替代生产测试。代码任务必须有非零匹配测试数，测试未运行不得done。

## 退出标准与证据

以上断言全部通过；没有新增未经审查的副作用路径；原功能不回退。将实际命令、退出码、文件变更、scenario ID 和已知限制写入 `execution/evidence/P14-T01.json`，status=passed后才更新STATE为done。没有提交写gitCommit=null；没有真实平台的证据写not_run而非passed。
